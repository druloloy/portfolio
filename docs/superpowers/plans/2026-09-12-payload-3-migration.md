# Payload 2 → 3 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the portfolio from Payload 2.30.3 / Next 13.5.2 to Payload 3.89.0 / Next 16 / React 19, with Lexical as the only rich-text editor, without losing the front end or its behaviour.

**Architecture:** Scaffold a fresh Payload 3 app from the official website template layout, port the config, collections, blocks, fields and front end into it, and run schema migrations against a Supabase **staging** branch. Production is touched only at the final cutover, from generated migration files, never by a live schema push.

**Tech Stack:** Payload 3.89.0, Next 16.3.5, React 19, `@payloadcms/db-postgres` 3.89.0 (Drizzle), `@payloadcms/storage-gcs`, Lexical, TypeScript 5, Vitest, SCSS modules, GSAP + Lenis.

**Spec:** `docs/superpowers/specs/2026-09-03-portfolio-audit-roadmap.md` (the audit this work closes out — F6 duplicate editors is resolved here; F1/F1a/F1b caching and revalidation must survive the port).

## Decisions taken (owner, 2026-09-12)

| Decision | Choice |
|---|---|
| Target version | **Payload 3.89.0.** `payload@latest` is 3.89.0; 4.0 exists only as `canary`, so v3 *is* current. |
| Database | **Supabase staging branch/project**, session-mode connection (port 5432). Never the production transaction pooler (6543). |
| Rich text | **Drop Slate, Lexical only.** Existing Slate content must be converted. |
| Approach | **Fresh scaffold, port across**, per Payload's own migration guide. |

## Global Constraints

- **Every `@payloadcms/*` package must be exactly `3.89.0`.** v3 requires all core and plugin versions synced; mismatches fail at runtime, not install.
- **Next must satisfy `>=16.2.6 <17.0.0`** (from `@payloadcms/next@3.89.0` peer deps). Use 16.3.5. The 15.x windows in that range are narrow — do not target 15.
- **React and react-dom must be 19** (`^19.0.1 || ^19.1.2 || ^19.2.1` per plugin peers).
- Node `^18.20.2 || >=20.9.0`. Local is 22.22.0 — fine.
- **`DATABASE_URI` must point at staging for every task in this plan.** Verify the port is 5432 before any command that can touch schema. A 6543 URI is the production pooler — stop.
- **Conventional commits, no attribution trailer, no `--author`.** Author and committer stay `druloloy <dru.loloy@gmail.com>`.
- Windows: `yarn` resolves only in PowerShell; never read an exit code after a pipe.
- **Brand values frozen:** no colour, type, border, shadow or spacing changes. SCSS modules port byte-for-byte unless a task says otherwise.
- **The 19 existing tests must stay green** and keep testing the same behaviour.
- **Standing regression check** (carried from the GSAP/Lenis work — run after *any* change touching the projects section): real wheel scrolling reaches `maxScroll`; the stacks section and footer are reachable; desktop has no `pin-spacer` and sweeps +505 → −343; mobile has exactly one `pin-spacer` reserving the sweep distance and every card lands centred.

## File Structure

Target layout, taken from the official v3 website template (`payloadcms/payload/templates/website`), which this repo is descended from. Note v3 **flattens** `src/payload/*` up into `src/*`.

```
src/
  app/
    (frontend)/          <- everything currently in src/app except `next/`
      layout.tsx
      page.tsx
      [slug]/page.tsx
      posts/[slug]/page.tsx
      projects/[slug]/page.tsx
    (payload)/           <- generated by the scaffold, do not hand-write
      admin/[[...segments]]/page.tsx, not-found.tsx
      admin/importMap.js
      api/[...slug]/route.ts
      api/graphql/route.ts
      api/graphql-playground/route.ts
      custom.css
      layout.tsx
    next/                <- our own routes, kept: revalidate, preview, exit-preview
  collections/           <- from src/payload/collections
  globals/               <- from src/payload/globals
  blocks/                <- from src/payload/blocks
  fields/                <- from src/payload/fields, MINUS richText/ (Slate)
  components/            <- from src/payload/components (admin UI)
  hooks/                 <- from src/payload/hooks
  utilities/             <- from src/payload/utilities
  payload.config.ts
  payload-types.ts
root:
  next.config.ts         <- replaces next.config.js, wrapped in withPayload
  tsconfig.json          <- ESM, bundler resolution, @/* alias
  vitest.config.mts
```

**Deleted outright:** `src/server.ts`, `src/server.default.ts`, `nodemon.json`, `scripts/dev-local.js`, `src/payload/fields/richText/` (Slate), `src/payload/dotenv.js`, `eject.ts`.
